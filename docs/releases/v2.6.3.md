# KubeBolt 2.6.3 — Kobi traces a rotated credential to its source, and Home answers for the cluster it names

Drop-in over 2.6.2. No schema change and no migration, and the agent stays on
**1.4.9**. The chart adds one read-only RBAC rule, for External Secrets
objects. It does nothing in a cluster without the operator.

## Kobi traces a rotated credential to its source

When a database starts rejecting a workload's password, there are three
possible causes:

- the pods still hold the old credential;
- the cluster never received the new one;
- the source and the database disagree.

Only the first is fixed by a restart. Kobi had no way to tell them apart, and
when the credential came from a cloud store through External Secrets, it could
not see which secret that was. The synced Secret points at its ExternalSecret,
but KubeBolt could not read the ExternalSecret, so Kobi guessed the secret's
name.

- **Kobi reads External Secrets objects.** `get_resource_yaml` reads
  ExternalSecrets, SecretStores and ClusterSecretStores (v1, or v1beta1 on
  older operators). It gets the remote key, the store's provider and region,
  whether the last sync worked, and when it last refreshed. These objects hold
  references only, and a store's inline credentials are hidden.
- **A procedure for credential errors.** Kobi compares the Secret's last write
  with the pods' start and the first failure, and only suggests a restart when
  the cluster already holds the new credential. A `refreshTime` more than two
  refresh intervals old means the sync has stopped, even while the
  ExternalSecret still says Ready.
- **The change, named at its source.** With the AWS connector, Kobi asks
  Secrets Manager when that exact secret rotated, and CloudTrail who rotated it.
  It never lists the account's secrets and never reads a value.

## A dependency behind an ExternalName Service is classified where it leads

Network flows name a dependency reached through an ExternalName Service by
that Service. `get_external_connections` therefore called it in-cluster and
told Kobi not to use a cloud connector for it, even when it was a managed
database in the cloud. The chain of ExternalName Services is now followed to
where it leaves the cluster, and that address is classified. The answer also
names the cluster's own cloud provider.

## Home and Fleet leave out silenced insights

Home and Fleet read each cluster's health from `/insights/summary`, which
ignored mutes. A silenced warning kept a cluster amber there while its Overview
said healthy. A critical still shows through a mute, as it does everywhere else.

In Home's «While you were away», a silenced episode never takes a row from one
that is not silenced. It reads *muted* and is never the report's "longest"
sentence.

## Home's links answer for the cluster they name

Home covers every cluster, but some of its links still answered for the
selected one:

- **«While you were away».** An episode from another cluster now switches to
  that cluster before it opens. *See all bursts* and *open full history* cover
  every cluster over the report's own window.
- **Kobi's card.** It names each conversation's cluster, and one from another
  cluster opens there. The ask box names the cluster it will ask about.

## Upgrading

```bash
helm upgrade kubebolt oci://ghcr.io/clm-cloud-solutions/kubebolt/helm/kubebolt \
  --version 2.6.3 -n kubebolt --reset-then-reuse-values
```

Use the namespace you installed into: `helm list -A | grep kubebolt` shows it.
`--reset-then-reuse-values` needs Helm 3.14+; passing your values file (`-f`)
works too. Do not use `--reuse-values`: it keeps the previous chart's defaults,
pinned image tags included. Step by step, what to expect, rollback, and what
each version asks of you when you skip some:
[Upgrade](https://github.com/clm-cloud-solutions/kubebolt/blob/main/deploy/helm/kubebolt/README.md#upgrade).

If you manage KubeBolt's RBAC yourself instead of through the chart, grant
`get`, `list` and `watch` on `externalsecrets`, `secretstores` and
`clustersecretstores` in `external-secrets.io`. Without it, Kobi cannot read
those objects, and nothing else changes.

The agent stays on 1.4.9: there is no agent release with 2.6.3.
