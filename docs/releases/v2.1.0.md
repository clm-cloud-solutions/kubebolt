# KubeBolt 2.1.0 — insights grow a lifecycle

Homologates **EE 2.1.0-e2**. API + web. No schema migration in the SQL sense:
the embedded store gains seven buckets (`insight_episodes`,
`insight_transitions`, `insight_mutes`, `insight_mute_keys`,
`user_dashboard_seen`, `operational_episodes`, `rule_policies`), created on
first boot; every existing bucket is untouched and a 2.0.x binary ignores the
new ones if you roll back. The agent does not need to move.

The theme: an insight stops being a light that is either on or off, and
becomes something with a **history, an owner and a policy**. The product
detected everything and could neither remember it, nor shut up about the parts
you had already decided to tolerate.

## What's in it

**Episodes and history.** Every insight now opens an *episode* — a durable row
with a timeline (opened, flapped, severity moved, muted, resolved, expired),
a 10-minute reopen cooldown (a fingerprint that re-fires within it is the
same episode flapping, not a new finding and not a new notification) and an
expiry watchdog (`KUBEBOLT_INSIGHT_EXPIRE_TTL`, 15 min): a firing episode
whose cluster stopped evaluating flips to `expired`, its head row follows,
and the Active list stops showing a condition nobody can verify. The Insights
page gains **Active | History** with server-side filters and pagination, and
each episode has a detail page with its full timeline and recurrence. History
answers for dead clusters — their persisted display name survives the
cluster. Retention rides the hourly pass with the insights horizon
(`KUBEBOLT_INSIGHTS_RETENTION_HORIZON`); firing episodes are never pruned.

**Silences are a first-class layer.** Muting is per (cluster, rule, resource),
always with an expiry or *until resolved* — a permanent mute demands a written
reason. Mutes subtract everywhere insights are shown or counted (Overview KPI
included); critical severity pierces them; every mute and unmute lands in the
episode timeline and the audit trail with the actor's name. Admin → Insights →
**Silenced** lists them with cluster names, not UUIDs.

**The shift report.** Home's greeting tells you what happened while you were
away: a narrative of operational bursts (deterministic clustering — same
window in, same episodes out: node rotation, node pressure, mass rollout, or
an honest "unknown burst"), the worst episode linked, and suppression
counters. Event semantics: it reports what *happened* in your absence window
(hung from the moment Home last rendered for you), not standing state, so it
goes quiet when nothing did.

**The rule matrix, global layer.** Rules split into *malfunctions* (severity
locked — only the numeric bar moves, never off) and *expectations* (severity
is the dial, off included). Admin → **Insights → Rules** carries the 24 shipped
rules with their class, description and knobs, the install-wide override per
rule, and the honesty column **Ignored 30d** (closed without ack, action or
mute). A rule turned off is still evaluated and **counted**: the Insights
page says how many findings the policy hides.

**Kobi answers without a cluster.** `/copilot/chat` moves outside the
connector guard: with no cluster connected Kobi still answers about itself,
KubeBolt and Kubernetes (docs tool included) and explains the missing cluster
in its own voice instead of a bare 503.

## Behaviour changes to know about

- Overview and insight counts **subtract muted insights** (critical still
  pierces). The Insights page is the only surface that can show them, behind
  `includeMuted=true`.
- `GET /insights` gains `hiddenByProfile` and `profile`; the `items` /
  `total` shape is unchanged.
- Episode ids are the occurrence ids the ring already carried, so Kobi
  triggers and action proposals do not re-key.
- The Insights sidebar item now also opens Admin → Insights (`/admin/insights`)
  for admins; `/insights/episodes/:id` is a cluster-scope route.

## Not in OSS (EE-only) — from 2.1.0-e2

- The capability registry (#50) and everything it feeds: Plan & usage
  states, capability transitions on the episode detail, capability lines on
  the shift report.
- Per-environment policy layers, the Environment tuning tab, D-1 grace and
  the classification chip on Fleet; the closed-set migration.
- Autopilot's `recommendation_ready` terminal state and its backfill.
- `tenant_id` on the request log line, the self-cluster identity closure
  (#30) and the SaaS audit additions of #53.

## Upgrading

```bash
helm upgrade kubebolt oci://ghcr.io/clm-cloud-solutions/kubebolt/helm/kubebolt --version 2.1.0
```

Nothing to migrate: the buckets are created on boot. An episode is born with
the first evaluation after the upgrade; there is no backfill from the
occurrence ring.

## Verification

The Enterprise in-vivo guide (`docs/Kubebolt-insight-lifecycle-guia-pruebas.md`
in the EE repository, phases 2 and 3) applies to this build on kind: open an
episode, flap it inside the cooldown, let the watchdog expire it after the
agent leaves, mute and unmute a resource, and read the shift report after
leaving Home for a while. Operator validation pending.
