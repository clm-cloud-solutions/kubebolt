# KubeBolt 2.0.0 — three pillars: Security & Compliance, Fleet, and a Home that says what needs you

2.0.0 is the first OSS release that tracks KubeBolt EE release by release. It
homologates **EE 2.0.0-e2** — everything in that release that does not depend on
the multi-organization SaaS machinery — as seven pull requests into `develop`
(#184 – #190), one per area, and closes the line with this note.

It is a drop-in upgrade: no schema migration, no configuration change required.
The embedded store gains two buckets (`findings`, `runtime_events`) that are
created on first boot; every existing bucket is untouched. Any agent from the
1.x line (≥ 1.0) keeps working — see [COMPATIBILITY.md](../COMPATIBILITY.md).

Two things change on screen the moment you sign in, both deliberate: **you land
on Home instead of the first cluster's overview**, and **the sidebar has two
menus** — a global one (Home · Fleet · Security · Administration) and the
per-cluster one you know. Details in §5.

## 1. Behaviour changes to know about

- **Sign-in lands on `/home`.** Deep links still win (`state.from` is honoured),
  and `/` stays the cluster Overview — no URL moved. See `landingAfterAuth` in
  `apps/web/src/utils/routes.ts` for the reasoning.
- **client-go's streaming initial list is disabled by default.** Over the agent
  tunnel a dropped watch event meant an object never entered the informer cache
  while `WaitForCacheSync` still reported success — a short list served as
  healthy (measured: 101 of 117 ReplicaSets). Informers are back to LIST + WATCH.
  `KUBEBOLT_WATCHLIST_CLIENT=true` re-enables it, and only makes sense when every
  cluster is reached directly. A cache audit now logs when the cache disagrees
  with a fresh list.
- **`GET /search` is served outside `requireConnector`.** ⌘K keeps answering when
  the active cluster is down; the single-cluster path returns its own 503.
- **The Helm chart's ClusterRole gains read access to the scanner CRDs**
  (`aquasecurity.github.io` and `wgpolicyk8s.io` reports). Upgrade the chart to
  see findings; without the rule the Security page stays empty and logs a 403.
- **Sidebar collapse state is stored per menu** (`kb-sidebar-groups-collapsed:cluster`
  / `:global`). The old key is ignored, so groups show their defaults once.
- **Active-series metering states its window and bills p95, not peak.** The
  cardinality endpoint queries a 15-minute window (`usage.ActiveSeriesWindow`)
  and the billable gauge is the p95 of the samples inside it.
- **Retention is now a scheduled pass** with one horizon per store (see §7).
  Nothing was pruned before 2.0.0 unless you did it by hand.

## 2. New pillar: Security & Compliance

A findings store on BoltDB and four signal providers, all OSS:

| Provider | What it brings | How it arrives |
|---|---|---|
| **Trivy Operator** | image CVEs, workload misconfiguration (ConfigAudit), exposed secrets (the secret itself is never stored), RBAC assessment, CIS via `ClusterComplianceReport` | swept from the report CRDs every 10 minutes |
| **Kyverno** | PolicyReports → policy violations (resource in `scope`, autogen duplicates collapsed) | swept |
| **Falco** | runtime events, live feed | pushed to `POST /ingest/falco` with a cluster-scoped agent token |
| **OpenCost** | cost samples for the Fleet and Home spend figures | queried from the embedded VictoriaMetrics |

**Four lenses instead of one ranked list** — `/security` (vulnerabilities),
`/security/configuration`, `/security/permissions`, `/security/compliance` — plus
`/security/runtime`. Each tab is a route so it can be linked and survives a
reload. The detail list is **workloads, not findings**: one image with 47 CVEs is
one thing to fix, shown with its blast radius. A CIS control names the resources
that fail it. Findings are deduplicated by fingerprint, keep their own clock (not
the scanner's), and a rollout is not read as a new vulnerability. The page renders
when the cluster is unreachable instead of blocking on it — `/findings*` and
`/runtime-events` are served outside `requireConnector`.

Endpoints: `GET /findings`, `GET /findings/workloads`, `GET /findings/{fingerprint}`
(re-reads the scanner report live, degrades to the stored row), `GET /runtime-events`,
`POST /ingest/falco`. Guides: `docs/integrations/{trivy-operator,kyverno,falco,opencost}.md`;
a ready-to-apply `deploy/test/trivy-operator-values.yaml`.

## 3. New pillar: Fleet

`/fleet` shows every cluster at a glance **without connecting to any of them**:
health from `/insights/summary` (the same source as each cluster's Overview, so
the two cannot disagree), findings per cluster, and cost / nodes / pods from four
`scope=fleet` instant queries folded client-side. Grid and table views, sorted
worst-first; a card opens the cluster. Node counts read from the **agent stream**,
not from OpenCost, and a missing cost is explained rather than dashed.

- **`GET /search?scope=fleet`** fans the name search out across every cluster you
  can see (3 s per cluster, 25 hits per cluster, 50 merged, sorted by cluster then
  name so identical workloads render adjacent). Hits carry a `cluster` label and
  the response reports `clustersSearched`. ⌘K offers "This cluster / All
  clusters" and opens in fleet scope on global pages.
- **`?scope=fleet` on `/metrics/query` and `/metrics/query_range`** drops only the
  `cluster_id` pin so `by (cluster_id)` roll-ups can span the fleet. The tenant
  pin stays, and an empty allowed set fails closed. `pv_hourly_cost` joined the
  scoped metric families — an unscoped `sum(pv_hourly_cost)` had been summing
  every cluster's volume cost.
- Each cluster now reports its **profile**: cloud provider, region and Kubernetes
  version (`cloudProvider`, `region`, `kubernetesVersion` on `/clusters`), detected
  from node labels and the server version. The dashboard header, empty since
  1.22.0, shows them again.

## 4. Home

`/home` answers "what needs me this morning, anywhere?" before you pick a
cluster: a header tinted by the worst thing on the page, four cards (clusters ·
pods · monthly spend · critical findings) folded from the same roll-up Fleet uses,
a **prioritised Attention list** (unreachable clusters, agents that never
connected, agents that are up but silent, critical findings — each row links
where you act), a per-cluster breakdown when more than one cluster reports, your
recent Kobi conversations with a box that actually asks, and the Cost and Security
panels. Nothing on it is veiled in OSS: `usePlan` fails open, and the single
tenant's `self-hosted` plan resolves to "everything included".

## 5. Two altitudes

The app has always had two heights — the fleet and one cluster — and nothing
declared which screen was which. Now `apps/web/src/utils/scope.ts` does: every
route is `global` (Home, Fleet, Security, Administration — read with your tenant,
never through a connector), `cluster` (Overview, the resource lists, Map,
Insights, Events, Clusters management, resource detail) or `public` (Login). The
table replaces three string checks that had drifted apart, and a test walks the
registered routes and fails on an undeclared one or a dead prefix.

What consumes it:

- **Sidebar** — a global menu and a cluster menu; every item points at its own
  altitude (enforced by test) so a click never swaps the menu under the cursor.
  Overview and the seven resource groups live only in the cluster menu;
  Administration only in the global one. Narrower rail for the short menu.
- **Topbar** — outside a cluster the LIVE pill, node count, port-forwards, the
  Dashboard/Map toggle and the New-resource button disappear (they describe, or
  write to, a cluster you are not looking at). Inside a cluster a "Fleet /"
  breadcrumb is the way out. From global, the switcher's active row reads
  "Open →" and enters the cluster.
- **Layout** — the resource WebSocket is mounted only in cluster scope, so global
  pages stop receiving one cluster's informer firehose. Global routes (and
  `/clusters`, the emergency exit) render even when the active cluster is
  unreachable.

## 6. Cluster, Kobi, audit and the rest

- **A monitored cluster no longer reports itself disconnected** while its runtime
  is parked; a cluster's display name survives being de-registered; a failed
  pooled runtime is evicted and re-spun when its agent re-registers.
- **`GET /insights/summary`** — per-cluster severity counts behind the
  `WithClusterScope` middleware; **`GET /clusters/names`** — display names for
  labels; `CanonicalClusterID` unifies context names and agent cluster ids.
- **Kobi can ask for 7d / 14d / 30d** — each point of the workload-metrics tool is
  now a bucket aggregate rather than an instant sample, so a month is not twelve
  15-minute windows. The Copilot usage page breaks spend down **by cluster**; the
  model catalog is a single module; the floating panel keeps clear of the Topbar.
- **Audit** — entries carry a class (`action`, `access`, `admin`); exec, port-forward,
  file browsing, YAML apply and every admin write emit one; `GET /admin/actions?class=`
  filters. Kobi conversations are capped per user.
- **UI** — six charts gained legends; KPI and efficiency cards are shared modules;
  numbers that disagreed across dashboards were reconciled; node names are
  shortened on the nodes strip; **adding a cluster is a component** (`AddClusterButton`)
  offered from Clusters and Fleet; the sign-in shell carries the edition's feature
  list and tagline from the registry.

## Upgrading

```bash
helm upgrade kubebolt oci://ghcr.io/clm-cloud-solutions/kubebolt/helm/kubebolt --version 2.0.0
```

- Upgrade the chart (not just the image) so the ClusterRole picks up the scanner
  CRD rules.
- Install Trivy Operator, Kyverno or Falco on a cluster to populate Security;
  the integrations catalog offers each one with its install and configure path.
- After sign-in you land on Home; bookmark `/` if you prefer the cluster Overview.
- Nothing to migrate: new BoltDB buckets are created on boot, old ones untouched.
