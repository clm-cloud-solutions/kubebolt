# KubeBolt 2.6.1 — Kobi reads more of ECR, and the traffic map shows only what is talking

Drop-in over 2.6.0. No schema change and no migration. The agent moves to
**1.4.9**, which stops its flow series from only growing. If you use Kobi's AWS
connector, its role needs two more actions; see *Kobi reads more of ECR*.

These fixes come from an AWS lab: EKS, Cilium chained to the VPC CNI, Hubble,
the AWS connector, and Falco on kernel 6.18.

## Kobi reads more of ECR

Kobi could not investigate an ECR pull failure, even with the role the connector
drawer prints: the operations KubeBolt allows stopped at the repository list,
the image list and the repository policy. It now also reads, never image layers
or manifests:

- an image's **scan findings** (`DescribeImageScanFindings`);
- a repository's **images and tags** (`ListImages`, `ListTagsForResource`);
- the repository's **lifecycle policy** (`GetLifecyclePolicy`), the usual answer
  to a tag that is suddenly `manifest unknown`. With CloudTrail
  (`PolicyExecutionEvent` for lifecycle expiries) it says who or what removed it.

For an ECR destination its first read is now `DescribeImages` with the
repository from the pod's image, instead of listing every repository: a role
limited to some repositories refused that list.

**Update the connector role.** A role created before 2.6.1 lacks
`ecr:GetLifecyclePolicy` and `ecr:List*`; until they are added, those reads are
refused and everything else works as before. The connector drawer prints the
updated policy: add the two actions to the read-only `Allow` statement and to
the `NotAction` list of the `NothingElseThroughMCP` deny.

## The traffic map shows only what is talking

The Traffic layout promises the last minutes of traffic. It also drew:

- **red edges to `ff02::2` after every pod restart** — the IPv6 Router
  Solicitation a pod sends when its interface comes up, dropped by an IPv4-only
  datapath. Multicast and unspecified destinations are not drawn;
- **destinations idle for hours**, at rate 0: the agent kept a counter for every
  address and pod pair since it started. With a destination that answers each
  lookup with a new address (S3), "(external)" collected dozens. Edges with no
  traffic in the window are not drawn, between pods or to an address;
- **the API server as bare IPs** (on EKS its endpoints are control-plane ENIs in
  your VPC). They are named `kubernetes.default.svc`;
- **traffic to a node** (the kubelet) as traffic to whichever `hostNetwork` pod
  on that node was listed last. It now goes to the node, by name.

Kobi's `get_external_connections` reads the same edges: idle destinations and
`ff02::2` no longer reach it.

## An integration installed after the cluster connected shows up

Whether the optional CRDs (cert-manager, Argo CD, VPA, the Cilium policies) were
installed was decided once, when the cluster connected. Cilium installed
afterwards stayed "not detected" on the Overview, and Kobi said its policy CRDs
were not installed next to existing CiliumNetworkPolicies, until the API
restarted. KubeBolt now checks again every two minutes, both ways: installed
becomes available, removed becomes "not detected".

## Agent 1.4.9

- **Flow keys idle for 15 minutes are forgotten.** The agent kept every Hubble
  flow key (pod pair, pod → address, DNS answer) for its pod's whole life and
  sent all of them every 5 seconds, so pod restarts and rotating cloud addresses
  made its active series only grow. A forgotten key stops being sent; nothing
  already stored is lost. Until now, restarting the agent was the only way to
  clear them.
- **The node-exporter discovery finds kube-prometheus-stack's** by default
  (`app.kubernetes.io/name=node-exporter|prometheus-node-exporter`): the most
  common production install got no node-exporter target and a grey coverage
  chip, with no error.

## Falco guide

[`docs/integrations/falco.md`](../integrations/falco.md) puts the ingest token in
a Secret (`falcosidekick.config.existingSecret`) instead of the Helm values, and
states that kernel 6.18 (Amazon EKS AL2023 from November 2026) needs **Falco
0.45.1 (chart 9.2.1) or later**: older versions crash-loop on the BPF verifier.

## Upgrading

```bash
# The backend
helm upgrade kubebolt oci://ghcr.io/clm-cloud-solutions/kubebolt/helm/kubebolt \
  --version 2.6.1 -n kubebolt --reset-then-reuse-values

# Then the agent, in every cluster that runs one (with that cluster's kubectl context)
helm upgrade kubebolt-agent oci://ghcr.io/clm-cloud-solutions/kubebolt/helm/kubebolt-agent \
  --version 1.4.9 -n kubebolt-system --reset-then-reuse-values
```

Use the namespaces you installed into: `helm list -A | grep kubebolt` shows
them. `--reset-then-reuse-values` needs Helm 3.14+; passing your values file
(`-f`) works too. Do not use `--reuse-values`: it keeps the previous chart's
defaults, so the agent would keep its old node-exporter selector. Step by step,
what to expect, rollback, and what each version asks of you when you skip some:
[Upgrade](https://github.com/clm-cloud-solutions/kubebolt/blob/main/deploy/helm/kubebolt/README.md#upgrade).

2.6.1 also runs with agent 1.4.8; 1.4.9 stops the flow series from growing.

**AWS connector users:** add `ecr:GetLifecyclePolicy` and `ecr:List*` to the
role (see *Kobi reads more of ECR*).
