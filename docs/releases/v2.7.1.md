# KubeBolt 2.7.1 — Kobi reads a request once, an edit Kubernetes would undo is refused, and shutdown drains first

Drop-in over 2.7.0. No schema change and no migration. The agent stays on
**1.4.10**; there is nothing to upgrade in your clusters.

## Kobi reads a request once

The OpenCost that the agent's chart can bundle republishes some
kube-state-metrics families. In a cluster that also sends kube-state-metrics,
CPU and memory requests and node allocatable arrived twice with the same
value, and a sum doubled them: Kobi compared usage against twice the request
(15 % where it was 30 %), and the same path feeds its resource proposals.
Requests, limits and allocatable are now read once per container or node,
whichever source sent them. A metrics-only cluster's overview reads
allocatable and its volume claims once too.

## An Endpoints edit Kubernetes would undo is refused

The Endpoints page shows and edits EndpointSlices. A slice a Kubernetes
controller writes is rewritten within seconds: from its Service's selector,
or mirrored from the core `Endpoints` of a Service without one. Saving
answered OK and the change vanished. Now:

- Saving such a slice is refused with a 409 that says where to make the
  change: the Service, or the `Endpoints` the slice copies.
- That `Endpoints` can be read and edited as `coreendpoints` (YAML view and
  apply), and a mirrored slice's YAML tab opens it.

## The agent upgrade command fits your release

The out-of-date agent dialog, Kobi and the cluster list gave the wizard's
default command (`kubebolt-agent` in `kubebolt-system`). The command now
names the agent's own Helm release and namespace, read from the cluster, and
the cost source to drop when both OpenCost paths are on, which agent 1.4.10's
chart refuses.

## Kobi's panel

The panel takes the look of kubebolt.io's chat. Answers sit beside Kobi's face
at full width, your turn is a bubble, and the face follows what Kobi is doing,
an approved action and the rollout it watches included.

## Smaller fixes

- **Drains belong to the cluster they run in.** A drain is keyed by org,
  cluster and node: two clusters with a same-named node (every kind cluster
  has `kind-control-plane`) no longer refuse each other's drains, and
  re-attaching to or cancelling a drain finds only the caller's own.
- **Port-forwards:** stopping one requires the org that created it, and with
  authentication disabled the port-forward list no longer comes back empty.
- **Shutdown drains first.** On SIGTERM the API lets in-flight requests finish
  (`KUBEBOLT_SHUTDOWN_TIMEOUT`, 20 s by default; keep it below the pod's grace
  period), records the close of terminals and port-forwards still open
  (reason `server shutdown`), and only then lets the agents go. It used to cut
  the agents first, so a request in flight lost its way to the cluster.
- **Metric names have a class.** A shared catalog says whether a metric name is
  core (what the agent sends, kube-state-metrics, the node-exporter names
  KubeBolt reads, cost, target health), a custom family, or unknown, by exact
  name. Nothing in this edition gates or counts by it yet; the agent's tests
  fail when it emits a name the catalog lacks.

## Upgrading

```bash
helm upgrade kubebolt oci://ghcr.io/clm-cloud-solutions/kubebolt/helm/kubebolt \
  --version 2.7.1 -n kubebolt --reset-then-reuse-values
```

Use the namespace you installed into (`helm list -A | grep kubebolt`).
`--reset-then-reuse-values` needs Helm 3.14+; passing your values file (`-f`)
works too. Do not use `--reuse-values`: Helm keeps the previous chart's
values, defaults included, so the chart's pinned image tags stay old. Step by
step, rollback, and what each version asks when you skip some:
[Upgrade](https://github.com/clm-cloud-solutions/kubebolt/blob/main/deploy/helm/kubebolt/README.md#upgrade).

This version asks nothing of an upgrade from 2.7.0. From an older version,
read 2.7.0's *Upgrading* first.
