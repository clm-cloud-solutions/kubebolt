# KubeBolt 2.7.2 — a store that does not answer is not a bad credential

Drop-in over 2.7.1. No schema change and no migration. The agent stays on
**1.4.10**; there is nothing to upgrade in your clusters.

## A store that does not answer is not a bad credential

Every token check answered a store failure the way it answers a bad token:

- **API keys** got 401 «invalid or expired token».
- **`remote_write`** got 401. Prometheus drops what a 401 refuses, so the
  samples were lost; in permissive mode the batch was accepted under the
  default tenant instead.
- **Falco's ingest** got 401.
- **The agent's gRPC channel** got `Unauthenticated`.

Now a failure to reach a verdict answers **503 with `Retry-After`**
(`Unavailable` on gRPC), which those clients retry, and never falls back to
the default tenant. A rejected credential keeps its 401/403.

## Insights survive an unreadable store

When the insight store could not be read, the engine took the failed read for
an answer:

- **An insight already open looked brand new.** It got a second episode, a
  reset first-seen time and a second notification.
- **A refresh rebuilt the record** and replaced the stored one, dropping its
  occurrence history.
- **The rule policies fell back to factory defaults** and stayed cached until a
  policy changed, so the rules you had turned off came back.

A read error now defers that insight to the next pass and leaves its record
alone. A failed policy read caches nothing, and the engine skips the pass.

## Smaller changes

- **`GET /health/db`.** It answers whether the API reaches its database, for
  an external monitor. This edition keeps its stores in process, so it answers
  `ok`; the route exists so editions with an external database can plug in
  their check. The Kubernetes probes stay on `/health`.
- **Expired sign-in sessions are pruned.** Every sign-in writes a refresh
  token. Nothing removed one that simply expired; the hourly retention pass now
  does.

## Upgrading

```bash
helm upgrade kubebolt oci://ghcr.io/clm-cloud-solutions/kubebolt/helm/kubebolt \
  --version 2.7.2 -n kubebolt --reset-then-reuse-values
```

Use the namespace you installed into (`helm list -A | grep kubebolt`).
`--reset-then-reuse-values` needs Helm 3.14+; passing your values file (`-f`)
works too. Do not use `--reuse-values`: Helm keeps the previous chart's
values, defaults included, so the chart's pinned image tags stay old. Step by
step, rollback, and what each version asks when you skip some:
[Upgrade](https://github.com/clm-cloud-solutions/kubebolt/blob/main/deploy/helm/kubebolt/README.md#upgrade).

This version asks nothing of an upgrade from 2.7.1.
