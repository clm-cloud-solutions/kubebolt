# KubeBolt 1.22.0 — Cost visibility (OpenCost), the dashboard redesign, a hardened Copilot stream, and auth hardening

1.22.0 brings OSS up to parity with the **shared** feature set of KubeBolt EE 1.22,
folding in every user-facing change homologated since 1.17.1. The version number is
now **aligned with EE** so the two lines track together. Each section below notes
the **EE release** it corresponds to, so you can cross-reference the two changelogs.

Drop-in over 1.17.1 — **no schema change, no migration**. The node agent bumps to
**1.3.0** (OpenCost sourcing) on its own cadence.

> **Why one release covers several EE versions.** OSS had accumulated homologated
> work (the dashboard redesign) on `main` without a cut, and the rest landed as one
> homologation pass. Rather than back-date intermediate tags onto already-published
> history, 1.22.0 consolidates the whole span **1.17.2 → 1.22.0** — but this note
> documents each EE version's contribution individually so nothing is lost.

## AI Copilot (Kobi) — SSE stream no longer cut at 15s on Gateway API — *(EE 1.17.3)*

On an Envoy Gateway deploy, the API `HTTPRoute` inherited Envoy's **15s route
default**, which cut the Copilot SSE stream mid-answer on deep analyses (a bare
"Load failed" in the browser).

- The API `HTTPRoute` now sets `timeouts.request` (default `"0s"` = no cap),
  configurable via `gatewayAPI.api.requestTimeout`.
- A quiet **SSE keepalive heartbeat** (every 15s) keeps a long, quiet turn alive.
- The ServiceAccount gains write on `gateways` / `httproutes` / `grpcroutes` so you
  can edit routes from the YAML tab.
- A dropped stream now shows a readable, recoverable message instead of the raw
  browser error.

## Dashboard redesign: scan → dive — *(EE 1.19.0)*

The dashboard is split into three sub-tabs that share the same header + range
selector but answer different questions:

- **Overview** — "is everything fine right now?" — a resource-efficiency band
  (used / idle-requested / free) with right-size callouts, an identity header with
  cloud provider · region, and workload health at a glance.
- **Capacity** — "how is the cluster consuming, and is it sized right?" — a summary
  strip, CPU / Memory / Network / Filesystem trends with deploy markers, Recent
  Deploys / OOMKills, and reclaimable right-sizing.
- **Reliability** — "what is the cluster actually serving?" — golden signals from
  Hubble L7 (error rate split 4xx/5xx, top traffic / latency, network drops),
  shown only when Hubble flow data is present.

Events now render **Last Seen / First Seen** dates in the resource Events tab and
the Events page.

## Dashboard metric clarity + light-mode green — *(EE 1.19.1)*

- Capacity shows a **pods** subset line beside the whole-node total, with scope
  tooltips so "pods vs node" is unambiguous.
- The efficiency band's "used" bar uses the status-green token in light mode.

## Nodes redesign + right-sizing scroll — *(EE 1.19.2)*

- A Nodes scan layer: a summary strip (ready / bin-packing / consolidation /
  under-pressure), a pressure-sorted grid, and condition badges.
- The right-sizing panel now scrolls its full list instead of capping at the top 10.

## Auth hardening (Phase 1) + JWT-secret floor — *(EE 1.20.2 + 1.21.0)*

- Changing a password **revokes every other session** (refresh tokens) and re-issues
  the caller's own cookie, so the current device stays signed in.
- **Rate limiting** on the auth endpoints (per-identity + per-IP, bounded memory).
- **Constant-time login** — no account enumeration via response timing.
- `KUBEBOLT_JWT_SECRET` shorter than 32 bytes now **fails boot** instead of signing
  with a weak key.

## Cost — per-cluster spend, powered by OpenCost (Beta) — *(EE 1.22.0)*

A new **Cost** sub-tab surfaces per-cluster spend and efficiency when OpenCost is
present. It's a client-side lens over metrics the agent already ships into
VictoriaMetrics — no new backend service:

- Spend run-rate + Allocated-vs-total (idle) trends; a KPI strip (monthly run-rate,
  idle, rightsizing savings, cost / pod, efficiency); a cost breakdown by
  namespace / workload / node; and $-priced rightsizing recommendations.
- Three ways to feed it, chosen in the "Add cluster" wizard: a bundled OpenCost
  sub-chart, scraping an OpenCost you already run, or reading cost families from your
  existing Prometheus (Mode C). The tab hides itself until cost data flows.

Requires the **1.3.0 agent** (below).

## Node agent 1.3.0 — OpenCost sourcing

The agent (separate cadence, tag `agent-v1.3.0`) can now source OpenCost
cost / allocation metrics three ways and forwards the cost families
(`node_*_hourly_cost`, `container_*_allocation`, `pv_hourly_cost`) into the existing
ingest that powers the Cost tab. Same v1.0 metric / label schema — drop-in with
backend ≥ 1.13.0. See `packages/agent/CHANGELOG.md`.

## Upgrading

Drop-in over 1.17.1 — no schema change, no migration.

```bash
helm upgrade kubebolt oci://ghcr.io/clm-cloud-solutions/kubebolt/helm/kubebolt --version 1.22.0
```

Bump the node agent separately to pick up OpenCost sourcing:

```bash
helm upgrade kubebolt-agent oci://ghcr.io/clm-cloud-solutions/kubebolt/helm/kubebolt-agent --version 1.3.0
```

Avoid `--reuse-values` on the agent upgrade so the new OpenCost values register.
Gateway API installs get the route-timeout fix automatically; set
`gatewayAPI.api.requestTimeout` to a finite value (e.g. `"600s"`) if you prefer a
bounded cap over the `"0s"` default.
