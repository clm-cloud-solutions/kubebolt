# KubeBolt 2.4.1 — the first cluster in three steps

Drop-in over 2.4.0. No schema change, no migration, no new setting. The agent
stays on **1.4.4**.

A new install had nothing to offer before its first cluster: Home said
"0 clusters · all reporting" over empty panels, and the add-cluster command
could be copied before it worked. This release gives that moment one first
step, and fixes what was found while walking it end to end.

| | Impact |
|---|---|
| **A new install had no first step** | Home with no cluster showed empty panels under "all reporting", and the setup wizard's Agent step tried to create the token Secret in a cluster that did not exist |
| **The add-cluster command could be copied before it worked** | a `<token-secret-name>` or `<kubebolt-host>` left in the command is a shell redirection, so the paste failed before Helm ran |
| **Home crashed with nothing registered** | `GET /clusters` answered `null`, and Home read `.length` on it |
| **A deep link lost its query at sign-in** | `/admin/insights?tab=rules` opened on the page's default tab after logging in |
| **Gateway traffic was not marked as public edge** | with the UI served off-cluster (`web.enabled=false`), `kbs_` service tokens were not refused from the internet |

## 1. The first cluster in three steps

With no cluster registered, Home, **Add cluster** and the setup wizard's
Agent step open the **first-cluster wizard**: name → install → go live.

- **Where the agent reaches KubeBolt.** An operator-configured ingest URL wins
  (TLS on). Otherwise the wizard uses the inferred external endpoint, or
  `host.docker.internal:9090` on the laptop path. The field is editable and
  checked: `host:port`, no scheme, never loopback — inside a cluster,
  `localhost` is the agent's own pod.
- **One install block.** The wizard issues the agent's token before it shows
  anything to copy, then hands over a single block: namespace and Secret
  through `--dry-run=client -o yaml | kubectl apply -f -`, then
  `helm upgrade --install`. Pasting it twice is safe.
- **Try it on a laptop.** kind, k3d or minikube, each run end to end with the
  agent.
- **Waiting.** Past the expected time it shows what to check and keeps
  watching instead of giving up.
- **Alternatives.** «Advanced setup» opens the full wizard; «Import a
  kubeconfig» stays one click away.

Home with no cluster shows this step and an 18-second product tour, and hides
the verdict pill and the shift report while there is nothing to report on. In
the **Add cluster** menu the agent comes first and is marked recommended. The
full wizard keeps **Copy** disabled while its command still carries a `<…>`
placeholder, and says what is missing. With a cluster already connected, the
setup wizard's Agent step keeps the per-cluster install; when KubeBolt runs
outside a cluster, an address field replaces the `<kubebolt-host>`
placeholder.

## 2. Fixes

- **`GET /clusters` answers `[]`** instead of `null` when nothing is
  registered (a Go nil slice). The web client also reads a `null` as an empty
  list.
- **The setup wizard's Agent step** stops saying "No cluster is connected yet"
  under the card that says one is.
- **A deep link keeps its query through sign-in.** The query travels with the
  path to the login page and back; sign-in pages are still never a
  destination, with or without a query.
- **The chart's API `HTTPRoute` sets `X-KubeBolt-Edge: public`.** The API
  refuses `kbs_` service tokens that arrive with that marker, and the web
  nginx sets it on every request it proxies. With the Gateway API enabled and
  `web.enabled=false`, the route goes straight to the API and nothing set it.
  The header is set, not added, so a client cannot send its own value.

## Documentation

`CLAUDE.md` and the web app's meta description describe KubeBolt as it is
today: the open-source Kubernetes operations platform, with Kobi. Autopilot,
plans, teams and billing belong to KubeBolt Cloud and the Enterprise edition.

## Upgrading

```bash
helm upgrade kubebolt oci://ghcr.io/clm-cloud-solutions/kubebolt/helm/kubebolt --version 2.4.1
```

The agent stays on 1.4.4; nothing to do there.

Do not use `--reuse-values` across chart versions; pass your values file
(`-f`) or `--reset-then-reuse-values`.
