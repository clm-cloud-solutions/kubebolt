# KubeBolt 2.3.0 — the app in the site's language, and a Kobi that reads the node's disk

Drop-in over 2.2.1. No schema change, no migration, no new configuration. The
agent stays on 1.4.1.

| | Impact |
|---|---|
| **The app read as a different product** | next to kubebolt.io and the sign-in pages, every headline row was a strip of small tiles on a cold dark palette |
| **Kobi could not read a node's disk** | since 2.2.0 the tool offered `metric=filesystem` and refused every call for it, so a DiskPressure question got "I can't read the disk" |
| **Two insight rules fired on healthy states** | `readiness-probe-failing` on crash-looping pods with no readiness probe, `hpa-maxed-out` on any HPA pinned at its maximum or unable to read its metrics |
| **«While you were away» became a wall** | after a month away it chained one sentence per burst — fifty of them |

## 1. The app in the site's language

**Every headline row is a row of `KpiCard`s**: a large figure with its unit,
one sentence, a minichart and a mono caption. Each row tells its stories with
different charts — a half gauge, rings, a sparkline, a status list — all filled
with the one status green. **`alert`** is reserved for the card whose number
asks for someone (criticals open, a node down, 5xx over the bar): its figure
takes the state colour and it is the only card that lights up.

- **Warm dark palette**, the site's neutrals and paper-toned text. Small mono
  labels now clear AA contrast. The light theme is unchanged.
- **Overview:** health as a half gauge, the busiest nodes as CPU/memory rings,
  pods over 24h, open insights by rule.
- **Home:** a neutral greeting card, «While you were away» drawn as a timeline
  of the window with up to three episodes, and the fleet row.
- **Fleet:** the fleet's shape (one cell per cluster by health, 7-day spend,
  pods per cluster, agent coverage) and cluster cards with a health pill and a
  24h pod line. A cluster with no data says why instead of leaving a gap.
- **Capacity, Reliability, Cost, Security and Nodes** move to the same rows;
  Cost and Nodes go from five cards to four.
- **Kobi → Usage** opens with a row of cards (sessions, session health, tokens,
  spend) instead of two rows of tiles.
- **Rows enter once.** Figures count up and the minicharts fill, card by card,
  the first time you see a page in a session — on cluster pages, once per
  cluster. Coming back, refreshing data or reduced motion shows the final
  value.

**The sign-in pages are one night scene.** Sky, aurora and horizon run edge to
edge behind both columns on every viewport; the form sits on a glass card; the
small text went from ~2.8:1 to ~6:1 contrast.

Fixed along the way: Reliability showed "—" for 5xx when no 5xx series existed
(it reads 0 %), and two captions rendered white because of an unresolved
colour token.

## 2. Kobi reads the node's disk

2.2.0 taught Kobi to answer DiskPressure with the node's disk fill. The tool's
schema and the prompt offered `metric=filesystem`, but the argument validator
kept its own list without it: every call was refused before a query ran.
Fixing it brought out four more problems on a path that had never run:

- **The fullest disk, not the first one.** With node-exporter a node reports one
  series per mountpoint, and only the first was read. The summary is now the
  fullest disk at each point, with `perMountpoint` naming which one.
- **Peaks, not samples.** On a 24h range (2-hour step) a fill that lasted minutes
  fell between two points. Disk now reports the peak of each step, like CPU and
  memory.
- **A refusal reaches the model.** Asking for a pod's disk is refused — a pod's
  usage is not the node's — but the refusal used to arrive as an empty series,
  which reads as idle. Every metric now carries an `error` when it was not
  measured.
- **Unit `percent`**, and the chat card draws **Disk** with one row per
  mountpoint.

The prompt no longer contradicts itself: two lines still said disk was not
exposed. Disk IO is still not exposed, and PVC fill is read with
`query_metrics` (`kubelet_volume_stats_*`). The metric list the schema offers
and the list the validator accepts are now one list.

## 3. Insights that fire on what they describe

- **`readiness-probe-failing`** fired on crash-looping pods that declare no
  readiness probe: between restarts the container passes through Running and
  Terminated, and a pod not Ready for two minutes read as a failing probe — next
  to the crash-loop and OOM insights for the same container. It now requires a
  declared readiness probe and a container run older than the 2-minute grace.
- **`hpa-maxed-out`** fired whenever `currentReplicas >= maxReplicas`, so an HPA
  pinned with `min == max`, or one showing `cpu: <unknown>`, was "at its
  maximum" forever. It now requires the controller's own `ScalingLimited=True`
  with reason `TooManyReplicas`, with CPU above target as the fallback when the
  condition is not published.

Expect fewer of both after upgrading; the ones that remain are real.

## 4. «While you were away» summarizes

Past three bursts, the shift report leads with one sentence — how many, how
many recovered on their own, the breakdown by kind — tells the three that
matter most (still-down first, then the largest) and links to the burst view
for the same window. Over a window longer than a day, times carry their date.

## 5. Smaller things

- `GET /copilot/config` returns `spendUnit`. OSS is bring-your-own-key, so it
  is always `usd` and Kobi's views show the estimated provider cost.
- The README screenshots were recaptured in the new card language.

## Upgrading

```bash
helm upgrade kubebolt oci://ghcr.io/clm-cloud-solutions/kubebolt/helm/kubebolt --version 2.3.0
```

Do not use `--reuse-values` across chart versions; pass your values file
(`-f`) or `--reset-then-reuse-values`.
