# KubeBolt 2.2.0 — Kobi sees the whole product, and tokens say which clusters

API + web. No migration: API tokens gain an optional `clusters` field inside
their existing BoltDB record (a token without it reads every cluster, as
before). The agent does not need to move.

The theme: Kobi — in the chat and through the MCP server your own LLM client
connects to — could read the cluster's live objects and little else. The
product already knew about security findings, insight history, bursts,
deploys, coverage, metrics and right-sizing; now Kobi reads all of it. And
because an MCP token is something you hand to someone, a token now says which
clusters it may read.

## What's in it

**Kobi reads the rest of the product.** New read-only tools, in the chat and
on `/api/v1/mcp`:

- `get_findings`, `get_finding_workloads`, `get_finding_detail` — the Security
  pillar: posture, workloads ranked by findings, one finding re-read live from
  its scanner. The image filter accepts the short reference form.
- `get_runtime_events` — Falco events, bounded and with secrets redacted.
- `get_insight_episodes`, `get_insight_episode`, `get_operational_episodes` —
  insight history and bursts, answered for clusters that are down. The prompt
  tells Kobi to check bursts before blaming a workload that died with its node.
- `get_fleet_summary` and `list_clusters` — the first tools that see more than
  one cluster; `list_clusters` answers even with no cluster connected.
- `get_recent_deploys`, `get_coverage` (what KubeBolt can and cannot see, and
  the agents behind it), `query_metrics` (PromQL, confined to the cluster),
  `get_right_sizing` (the same engine the Capacity page now reads from
  `GET /right-sizing` — the browser no longer computes it) and node filesystem
  metrics.
- `offer_cluster_switch` (chat only): one click that switches cluster and asks
  the question again there. A conversation stays with the cluster it started
  on; the history names it.

Tool results are redacted before they reach the model: secrets in logs,
environment variables, command lines, describe output and events are masked.
`list_resources` says which optional resources are not installed instead of
reporting them as forbidden, and per-resource tools accept the type as
Kubernetes names it.

**API tokens for MCP, and per-cluster tokens.** *Create API token* offers
**MCP only (read-only tools)**: the key reaches `/api/v1/mcp` and nothing
else, its role is fixed to viewer (on the server too) and it expires in 90
days by default. Every API token can be limited to some clusters, editable
later from its row; the limit holds on every read — resources, logs, metrics,
findings, insight history, bursts, mutes — and for a request that names no
cluster. A limited token cannot switch the active cluster or reach
administration, and no token can create or edit tokens.

**Metrics queries are confined by the store.** Every PromQL a caller writes
(the metrics endpoints and `query_metrics`) now reaches VictoriaMetrics with a
server-built filter that VM enforces on the parsed query. The previous
text rewriter left some shapes unscoped — bare metric names outside its prefix
list such as `up`, decoy labels, MetricsQL or-filters — which on a VM shared by
several clusters read the others' series.

**Insights carry evidence.** Rules can hand over what they saw; the
*Service has no ready endpoints* rule records the owner, the selector and how
long. The burst view is addressable by date.

**The chat costs less.** The static part of the prompt stays cached for an hour
(`KUBEBOLT_AI_CACHE_TTL`, Helm `copilot.cacheTtl`; `5m` restores the API
default), and the conversation itself is cached between tool rounds — most of
a session's cost was re-writing that prefix. The GPT-5.6 line no longer fails
on tool-carrying turns; newer models join the catalogue.

**Sign-in pages.** Rebuilt in the site's language — See. Understand. Operate.,
one card, the cluster console, an entrance per form — scaling on wide monitors
and scrolling on phones. The top bar and the Overview KPI cards size to their
own width, so a docked Kobi panel no longer breaks their labels.

## Upgrading

```bash
helm upgrade kubebolt oci://ghcr.io/clm-cloud-solutions/kubebolt/helm/kubebolt --version 2.2.0
```

Nothing to migrate. Existing API tokens keep reading every cluster. If an MCP
host was set up with an *Everything* token, replace it with an **MCP only**
one.

## Verification

On kind with two clusters: create an MCP-only key limited to one of them and
check that `list_clusters` names only that one, that a header naming the other
answers 403, that a request with no header lands on the allowed cluster, and
that `query_metrics` returns the same counts with decoy labels, or-filters and
bare names as without them.
