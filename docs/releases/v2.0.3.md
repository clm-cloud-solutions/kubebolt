# KubeBolt 2.0.3 — a cluster that would not open, Secrets that should never have been on the wire, and the Split Bolt

Drop-in over 2.0.2. No schema change, no migration, no agent bump, no new
configuration surface. Homologates **EE 2.0.3-e2**. The web bundle changes, but
the API can be deployed on its own — the WebSocket payload change deliberately
preserves the shape the deployed frontend already reads, so deploy the API first.

| | Impact |
|---|---|
| **A cluster reported "you do not have access"** | total loss of resource views on a cluster running both agent topologies (DaemonSet + promread); the message pointed at RBAC, where nothing was wrong |
| **Secrets were broadcast to every browser** | full Secret contents, unredacted, to every authenticated session regardless of role, every 30 seconds |
| **The permission probe invented denials** | the same cluster read 29/31, 15/31, 9/31 within one hour, with no RBAC change |
| **Live updates lagged** | real events were crowded out by traffic nobody asked for |
| **The product still wore the old mark** | logo, favicons, accent and Kobi's green were the pre-split brand |

## 1. A cluster that would not open

A cluster running the DaemonSet (proxy-capable agents) alongside a Mode C
`promread` Deployment became unreachable: every request returned `403 you do not
have access to this cluster`. The promread pod advertises no capabilities —
correctly, it is not the proxy — and registered one second after the DaemonSet;
`AddMetricsOnlyCluster` then deleted the cluster's agent-proxy context mapping,
so the request router could no longer resolve the context and the guard read
that as a denial.

`kube-proxy` is a property of an **agent**. Whether a cluster can be proxied is a
property of the **cluster**, the union over its live agents — and the decision
is now made that way. Restarting the agent was never the remedy and restarting
the API only re-rolled the race; both are fixed at the source. **An unresolvable
context now returns 503, not 403**: the UI renders its "waiting for agent" state
and self-heals instead of sending an operator to audit RBAC.

## 2. Secrets are no longer on the wire

The WebSocket broadcast carried the raw informer object. Secrets have an
informer like every other resource, so every Secret in the cluster went out **in
full** — `Data` is base64 of the real contents — to every authenticated browser,
on every change and on every resync. The redaction in this product guards the
YAML viewer only; `/ws` performs no role check, so a **viewer** received it too.

The client never wanted the body: it reads `metadata.namespace` and
`metadata.name` to invalidate a cache key and discards the rest. The broadcast
now carries a notification with `kind`, namespace, name and uid. The shape the
frontend reads is preserved, so the API can roll first.

## 3. Live updates got faster, which was not the goal

The hub's single run loop marshals each message inline and pushes to a buffer
that drops silently when full. Bursts of large objects caused head-of-line
blocking and silent drops of real events — a genuine pod transition could be the
message that arrived at a full buffer. With forty-byte notifications the queue
never fills.

## 4. The permission probe stops inventing denials

The agent-proxy client ran with client-go's defaults (QPS 5 / Burst 10) while the
probe issues 31 access reviews behind a concurrency limit of 10, plus one per
namespace. Queueing waits exceeded the probe's own 3-second deadline, and a
timed-out review was recorded as a **denial**. The probe now runs on a dedicated
client; the shared configuration is untouched because it drives ~46 informers
whose startup LISTs would otherwise fire at once over a single agent channel.

## 5. The informer resync moves to ten minutes

A resync re-delivers the cache that is already there, and this product's handler
notifies rather than reconciles, so thirty seconds bought nothing. Live updates
depend on the watch, which this does not touch. Ten minutes rather than zero: a
cheap safety net, not twenty times an hour.

## 6. Per-kind WebSocket subscriptions are gone

The client sent `{type, resources}` and the server read `{action, types}`, so the
subscription frame never applied and every client received every kind. The
mechanism is removed rather than repaired: with forty-byte notifications there is
little to filter. If it returns it should be designed against the `kind` field
this release puts on the wire, and changed on both sides in one release.

## 7. The Split Bolt

The product now wears the new mark: the Split Bolt logo (`KubeBoltLogo`),
favicons and touch icons, the brand green as the app accent (`--kb-accent`) in
both themes, and Kobi's sigil resolved to the same green. Sign-in, the efficiency
band and every accent-coloured control follow. The website (`site/`) carries the
same mark.

## Upgrading

```bash
helm upgrade kubebolt oci://ghcr.io/clm-cloud-solutions/kubebolt/helm/kubebolt --version 2.0.3
```

Deploy the API before (or together with) the web bundle. Nothing to migrate.

## Not fixed here

- Re-evaluating a cluster's mode when an agent unregisters: if the last
  proxy-capable agent leaves, the cluster never degrades — left out deliberately,
  agent channels reconnect every ~16 minutes and it would oscillate.
- Informer startup concurrency: every cluster connect still pays several seconds
  to the client rate limiter.
