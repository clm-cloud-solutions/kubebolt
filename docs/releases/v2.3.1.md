# KubeBolt 2.3.1 — every install path works as written, history on a laptop included

Drop-in over 2.3.0. No schema change, no migration. One new optional setting:
credentials for the metrics store. The agent moves to 1.4.3.

Found by installing every path the README promises — Helm, Homebrew, krew, the
release binary, the single container and Docker Compose — on a clean cluster,
the way a newcomer would, each with the agent installed from the UI and with
helm.

| | Impact |
|---|---|
| **The wizard could not issue the agent's token** | on a self-hosted install, "Generate token + create Secret" answered "No active tenant available" (since 1.17.1), so the agent's read + write mode could not be set up from the wizard |
| **Homebrew refused to install** | on a Mac whose Xcode or Command Line Tools lag behind macOS: "Your Xcode is too outdated" |
| **A laptop install kept no history, without a word** | and the agent ingest logged an error for every batch from every node |
| **A VictoriaMetrics that needs credentials could not be used** | only basic auth written into the URL worked; no bearer token |
| **Every agent reported version 1.0.0** | whatever release was running |
| **Kobi's conversations never expired** | on a self-hosted install, whatever the retention horizon said |
| **Kobi's estimated cost was low** | one-hour cache writes were priced as five-minute ones |
| **Security** | Go 1.26.9 and `golang.org/x/net` v0.60.0: CVE-2026-78667, CVE-2026-97031 and CVE-2026-78669, all HIGH |

## 1. The agent's token, from the wizard

Every flow that issues the agent's token — the first-run wizard, *Add
cluster*, the agent's install and configure dialogs — looked the caller's
organization up by the name a self-hosted install gives it, while
organizations are stored by id. None was found, and no token could be issued.
The token is issued under the default organization again, and the agent
authenticates with it.

## 2. Homebrew installs a cask

The formula only downloaded the binary published on the release, but a
formula without a bottle is a source build to Homebrew, and Homebrew refuses
to build when Xcode lags behind macOS — common right after a macOS upgrade.
KubeBolt now ships as a **cask**, for macOS and Linux: the same binary, without
those checks, and without the quarantine flag that made macOS block it. The
command does not change:

```bash
brew install clm-cloud-solutions/tap/kubebolt
```

**Installed KubeBolt as a formula before?** `brew upgrade` no longer updates
it. Switch once — your data stays in the directory you run KubeBolt from:

```bash
brew uninstall --formula kubebolt
brew install clm-cloud-solutions/tap/kubebolt
```

## 3. History on a laptop install

Homebrew, krew, the binary and the single container don't bundle a
time-series store. KubeBolt keeps history in the VictoriaMetrics at
`http://localhost:8428` unless `KUBEBOLT_METRICS_STORAGE_URL` points elsewhere
— and now **says so at startup**: the store in use and where it came from, or

```
history off: no VictoriaMetrics at http://localhost:8428; start one there or set KUBEBOLT_METRICS_STORAGE_URL, then restart
```

While the store fails — down, or rejecting the credentials — the agent ingest,
the API's own metrics and the active-series cap each log it **at most once a
minute** with how many attempts failed, instead of on every attempt.

The README now walks every laptop path to history: one command to start a
VictoriaMetrics, a `.env` file for the setting, and where the agent connects
(`host.docker.internal:9090` from kind or Docker Desktop; a container name on
the `kind` network for the single container and Compose).

## 4. Credentials for the metrics store

A VictoriaMetrics that asks for credentials — a managed one, or one behind
vmauth — can be the history store:

| Setting | Use |
|---|---|
| `KUBEBOLT_METRICS_STORAGE_TOKEN` | bearer token (wins when both are set) |
| `KUBEBOLT_METRICS_STORAGE_USERNAME` / `_PASSWORD` | basic auth |
| chart `metrics.storage.existingSecret` | a Secret with `token`, or `username` + `password` |

They go on every call to the store; the URL is never logged with a password.

```bash
kubectl -n kubebolt create secret generic kubebolt-vm-credentials --from-literal=token=<token>
helm upgrade kubebolt oci://ghcr.io/clm-cloud-solutions/kubebolt/helm/kubebolt --version 2.3.1 \
  -f my-values.yaml \
  --set metrics.storage.embedded.enabled=false \
  --set metrics.storage.externalUrl=https://vm.example.com \
  --set metrics.storage.existingSecret=kubebolt-vm-credentials
```

The store must be VictoriaMetrics (single-node, or vmselect/vminsert behind one
URL): KubeBolt writes through its import API, so Thanos, Cortex or a plain
Prometheus won't do. The docs no longer call it "Prometheus-compatible".

## 5. Agent 1.4.3 reports its version

The agent's version was a constant, so **Administration › Agents** showed
1.0.0 for every release. The image now carries its release version. Agent
1.4.3 also moves to Go 1.26.9 and `golang.org/x/net` v0.60.0. Same metric and
label schema — drop-in within 1.x.

## 6. Kobi

- **Conversations expire on a self-hosted install.** The retention pass looked
  for them under the organization's id, while a self-hosted install stores them
  under its name. **The first pass after upgrading deletes the conversations
  older than the horizon** (`KUBEBOLT_COPILOT_CONVERSATION_RETENTION_HORIZON`,
  2160h by default): raise it before upgrading to keep them longer.
- **One-hour cache writes are priced at 2× input.** Kobi caches its system
  prompt and tools for an hour, which Anthropic bills at 2× input; they were
  estimated at the five-minute 1.25×. The first question of each conversation
  on Sonnet 5 came out about a third low.

## 7. Security

- Go 1.26.6 → **1.26.9** on every build path (api and agent images, the release
  binaries the single container ships): CVE-2026-78667 (net/http) and
  CVE-2026-97031 (crypto/tls), both HIGH.
- `golang.org/x/net` v0.58.0 → **v0.60.0**: CVE-2026-78669 (HTTP/2), HIGH.
- **VictoriaMetrics and vmagent stay on v1.153.0**, built by their vendor on Go
  1.27.1 and x/net v0.59.0, which carry the same three CVEs. The fix ships in
  VictoriaMetrics v1.154.0, still a release candidate; the three are waived in
  `.trivyignore-thirdparty` until the pins move to v1.154.0 final. KubeBolt's own
  images carry none of them.

## Upgrading

```bash
helm upgrade kubebolt oci://ghcr.io/clm-cloud-solutions/kubebolt/helm/kubebolt --version 2.3.1
helm upgrade kubebolt-agent oci://ghcr.io/clm-cloud-solutions/kubebolt/helm/kubebolt-agent --version 1.4.3
```

Do not use `--reuse-values` across chart versions; pass your values file
(`-f`) or `--reset-then-reuse-values`. Homebrew users who installed the
formula: see section 2.
