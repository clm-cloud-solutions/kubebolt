# KubeBolt 2.0.6 — the shared seat

API-only drop-in over 2.0.5. No schema change, no migration, no agent bump, no
new configuration surface, and no web changes — the bundle version moves for
consistency only. Homologates **EE 2.0.6-e2**.

## Version map — EE 2.0.6-e2 → OSS 2.0.6

| EE commit | OSS |
|---|---|
| the per-organization accessor family — `ActiveContextFor`, `ConnErrorFor`, `ActiveAgentProxyClusterIDFor`, `activeContextForLocked` shared by `resolveRuntime` and `MetricsOnlyClusterID` — and every `package api` call site moved to it | yes, as a refactor |
| `shared_seat_test.go`: no read of the global slot in `package api`, debt budget zero | yes |
| `ListClusters` resolves the cluster UID through this org's runtime, never the global slot | not needed — one tenant, the global slot is that tenant's |
| system-package patch in the Autopilot image; findings #50–#56 | EE-only |

## What this is in OSS

The Manager exposes two parallel families of API, and both compile equally
well at the call site. One takes `ctx` and resolves per (tenant, cluster) from
the `RuntimeKey` the middleware stashed — `Connector(ctx)`, `Collector(ctx)`,
`Engine(ctx)`, `MetricsOnlyClusterID(ctx)`. The other takes nothing and returns
the single global "active" slot — `ActiveContext()`, `ConnError()`,
`ActiveAgentProxyClusterID()`. In a multi-organization install the global slot
belongs to whichever organization switched cluster most recently, so reading it
inside a request answered for the wrong tenant: EE 2.0.6 found that bug written
eleven times (a fleet card painting another org's provider, a 409 handing an
admin another org's cluster UID, Kobi told it was on the wrong cluster).

OSS has one tenant, so none of those symptoms can occur here. What this release
changes is the **shape of the code**, so the two editions keep the same
handlers:

- `ActiveContextFor(ctx)`, `ConnErrorFor(ctx)` and
  `ActiveAgentProxyClusterIDFor(ctx)` are the per-request replacements; they
  honour an explicit `X-KubeBolt-Cluster` and otherwise resolve to the active
  context, and a pooled runtime's own connect error is returned for a
  non-active cluster.
- `activeContextForLocked` is the single resolution shared by `resolveRuntime`,
  `MetricsOnlyClusterID` and the accessors above, so they cannot drift.
- The nine call sites in `package api` (the overview 503 texts,
  `requireConnector`, the Kobi session prefix and usage attribution, the
  agent-uninstall guard and its 409 body) use the per-request family.
- `shared_seat_test.go` makes the rule executable: any read of the global slot
  from `package api` fails the build; the budget is zero and can only go down.
- The global accessors stay on the Manager for boot and for callers outside
  `package api`, where there is no request to resolve against.

## Upgrading

```bash
helm upgrade kubebolt oci://ghcr.io/clm-cloud-solutions/kubebolt/helm/kubebolt --version 2.0.6
```

Nothing to migrate. No behaviour change in a single-tenant install.
