# KubeBolt 2.4.0 — KubeBolt watches itself, lit cards name who is failing, and a cluster keeps its place

Drop-in over 2.3.1. No schema change, no migration. Ships with agent **1.4.4**.

| | Impact |
|---|---|
| **KubeBolt watched everything but itself** | an API slow on its own routes, a late background job, a failing call to VictoriaMetrics or a Kobi that kept erroring showed up nowhere, unless a user complained |
| **A lit card said "1 degraded" and stopped there** | which pod, since when, and where to fix it took a second page and a search |
| **A cluster whose agent went away vanished — or kept reading healthy** | the cluster left the selector the moment its last agent disconnected; when it stayed, its cached state read as current: the node Ready, the pods Running |
| **A restart undid the operator's choices** | a deleted cluster came back, and an agent-only install booted with no cluster selected, every view answering "no cluster selected" |
| **Colour did not always mean something** | two cards lit for the same fact, posture counts glowed red forever, and the Topbar always said "Live" |

## 1. KubeBolt watches itself

**Administration › System › Health** is the API's own dashboard:
- replicas and memory, and the 5xx share;
- HTTP by route group (a 503 from a dead cluster is counted apart from the API failing);
- background jobs, late ones first;
- VictoriaMetrics measuring itself (`--selfScrapeInterval=30s`) and the API's calls to it;
- **agents and the tunnel**: live agent channels per replica, and the Kubernetes requests that crossed the tunnel by result (`ok`, `timeout`, `agent_closed`…), with p50/p95.

**Administration › AI › Health** does the same for Kobi:
- turns and how they ended, provider errors and what the fallback rescued;
- refusals and cut-short answers, empty or failed tool calls;
- model latency, cost, tokens and the prompt cache.

Every answer now takes a **👍/👎**; a 👎 can carry a reason and a comment, which
stays with its conversation and never reaches a metric. Kobi no longer shows
the provider's raw error in the chat: each class of error has a fixed message.

Both tabs read new series the API pushes to VictoriaMetrics every 30 s,
stamped with `instance`, `run_id` and `job=kubebolt-api`, so a restart is
never a hidden counter reset. They are dropped at both ingest doors if a
Prometheus scrapes `/metrics` and forwards them (`reason="reserved"`), and
Kobi's never count against the active-series cap.

To notice an API that is down, something outside it has to look:
- **External watcher.** `KUBEBOLT_EXTERNAL_METRICS_URL` pushes a copy of the health series (nothing with a tenant or a cluster) to an outside Prometheus such as Grafana Cloud. It comes with an importable dashboard, `deploy/grafana/kubebolt-platform-health.json`, and a guide, `docs/operations/external-watcher.md`.
- **Alert rules.** `deploy/helm/kubebolt/files/kubebolt-alerts.yaml` holds rules on the API and on Kobi, unit-tested with promtool. The chart renders them as a `PrometheusRule` with `metrics.alertRules.enabled`.

## 2. Lit cards say who, since when and where

A card lights when its number asks for someone. Now it also says who:
- Overview's Pods card reads "3 degraded · oomy-killer since 04:47 PM";
- Reliability reads "mostly orders-api · 0.2 req/s";
- Capacity names the workloads that were OOMKilled;
- Fleet names the worst cluster.

The name is a link to the resource or to the panel that holds the detail. The
tooltip lists the rest.

The same applies to Nodes, Cost, Security, Home, Kobi Usage and both Health
tabs. On Kobi Usage, "N sessions ended in an error" filters the table to those
sessions. A session the user canceled no longer counts as an error.

**One range control.** Every range selector is one dropdown, and a
resource's Monitor tab reads one range for all its charts.

**Colour says what the data means** (dark mode):
- **One fact lights one card.** Health gives the verdict, with a Critical / Warning / Healthy chip and the colour of its bevel; the card that lights is the one that lists the cases, Insights.
- **The figure never takes the state colour.** The glow, the chip, the bar and the caption carry the state.
- **Posture versus incidents.** Open CVEs never light their card; runtime threats do.
- **The Topbar pill tells the truth.** It reads Live, Delayed, Disconnected or Connecting.
- **Contrast.** Small tertiary text clears AA contrast.

Fixed along the way:
- `kb-*/NN` opacity classes compiled to nothing, so some hovers, tints and floating panels painted nothing;
- a KPI card without a link cut its unit ("83 workloads affecte…").

## 3. A cluster keeps its place

**When its agent goes, the cluster stays.** Registration through the agent is
durable: only Delete in Clusters removes a cluster. While no agent is
connected, the cluster says what it is showing:
- a «No contact with this cluster since …» banner;
- the Disconnected pill;
- «No contact» on the health card;
- `NO CONTACT` in Fleet.

Its health checks go `unknown` with "Last known: …". Kobi's
`get_cluster_overview` marks the overview as the last known state, because
KubeBolt cannot tell whether the agent, its node or the network went down.
When the agent comes back, the cluster recovers by itself.

**A restart keeps the operator's choices.**
- **Delete is permanent.** A deleted cluster no longer comes back: the delete also forgets its agents' records, which the API restores clusters from at boot.
- **Stale records expire.** A record left "connected" by an API that stopped with its agent on the line now expires. At boot, with the built-in store, it gets the boot time as its disconnect, and the 24-hour prune takes it unless the agent says hello again.
- **The selected cluster survives the restart.** With no selection at all (a kubeconfig with no current context, as in an agent-only install), the first cluster with a live agent is selected, by name, a few seconds after the agents connect.

## 4. Kobi on Claude Haiku 5.5 and Sonnet 5.5

- **Haiku 5.5** reasons by default in the chat. It also writes conversation titles and compacts long conversations, with reasoning off.
- **Sonnet 5.5** is selectable. Kobi's default stays on Sonnet 5.
- **The compaction model is a selector**: Automatic, the provider's catalog, or Custom for any other id.
- **Each model has its own rate card.** Haiku 5.5 bills the whole call at its long-context rate above a 100K-token prompt. Sonnet 5.5 and Fable 5.1 no longer borrow the cache-read price of the model whose name they share a prefix with.

## 5. Smaller things

- **remote_write catch-up.** A batch over the rate limit that is catching up after an interruption gets `503` + `Retry-After`, which Prometheus retries. A sustained overrun keeps the `429`. Ingest activity shows it as "catch-up deferred".
- **Falco.** Falco fields that arrive null are no longer stored or shown as `<nil>`.

## Agent 1.4.4

Chart-only security update: the agent's code is the same as 1.4.3. The chart's
vmagent sidecar (`scrape.enabled=true`) moves to v1.154.0.

VictoriaMetrics and vmagent move from v1.153.0 to **v1.154.0**, which reports

## Upgrading

```bash
helm upgrade kubebolt oci://ghcr.io/clm-cloud-solutions/kubebolt/helm/kubebolt --version 2.4.0
helm upgrade kubebolt-agent oci://ghcr.io/clm-cloud-solutions/kubebolt/helm/kubebolt-agent --version 1.4.4
```

- **Clusters no longer leave when their agent does.** A cluster whose agent has stopped stays listed as out of contact. If you relied on it disappearing, delete it in Clusters.
- **Old agent records start to expire.** On the first start, records the previous version left "connected" get a disconnect time. A cluster whose agent is gone for good drops off a day later, at the following restart, unless you delete it first.

Do not use `--reuse-values` across chart versions; pass your values file
(`-f`) or `--reset-then-reuse-values`.
