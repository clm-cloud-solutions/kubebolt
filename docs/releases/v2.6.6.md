# KubeBolt 2.6.6 — no gap in agent metrics across a VictoriaMetrics restart, and Azure MCP Server 4.0

A fix release over 2.6.5. There is no migration, and the agent stays on
**1.4.9**. The chart changes one default, the Azure MCP Server sidecar image
(see Upgrading).

## Agent metrics survive a VictoriaMetrics restart

The agent channel has no acknowledgement. When the API failed to write a batch
to VictoriaMetrics, the batch was lost after a log line. Every restart of
VictoriaMetrics (a deploy, a node rotation) left a permanent gap in every
cluster.

The API now holds a batch refused for a passing reason (connection error,
timeout, 5xx, 429) and writes it again once VictoriaMetrics answers. Batches
are written oldest first, with the samples' own timestamps. Up to 64 MiB is
held, about four minutes of a busy install; past that, the oldest batches are
dropped. A 4xx is not retried. In the lab, a 75-second stop left no gap. No
protocol change: agents from 1.0 get it too.

## Kobi

- **A connector's first call is read by its own answer.** Kobi attaches the
  connector's procedure in front of the first answer from that connector. How
  the call ended was read from the whole text, so the procedure's own words
  decided: the AWS procedure says "`not found`" about ECR tags, and a failed
  first AWS call read as *not found*, with the procedure's header given as the
  reason. The tool card and the tool-result metrics now read the call's own
  answer.
- **A field manager name is a claim.** `get_resource_yaml` lists each field
  manager's last write. Its note said the `kubebolt-autopilot` manager *is*
  Autopilot, but any client can write with any manager name. The note now
  lists the names KubeBolt uses and says a name is what the write claims to
  be, not who made it.

## Events without permission say so

Without RBAC access to events, the Events page, `GET /events` and Kobi's
events tool failed: the API returned a 500, and Kobi's tool hit a recovered
panic. They now report it:

- `GET /events` answers 403.
- The page shows *Access Restricted*.
- Kobi gets a permission error saying that seeing no events does not mean
  there are none.

## Azure MCP Server 4.0.0-beta.6

The Azure connector's sidecar moves to Azure MCP Server **4.0.0-beta.6**,
pinned by digest. The 3.0 line ships Alpine 3.24.2 with two HIGH CVEs (musl,
zlib), so both Trivy waivers for it are removed. Kobi's command allowlist was
reviewed against 4.0, and every command keeps its name. Advisor reads only the
configured subscription.

## Go 1.26.11

The API, the single image and the krew/Homebrew binaries are built on Go
1.26.11, for CVE-2026-97054 (net/http: an HTTP/1 server could read past
`MaxBytesReader`'s limit; HIGH). The bundled VictoriaMetrics v1.156.0 carries
the same CVE, and no VictoriaMetrics release is built on a fixed Go yet. It is
waived until the next one, by 3 December at the latest. It runs as a ClusterIP
Service that only the API calls.

## Upgrading

```bash
helm upgrade kubebolt oci://ghcr.io/clm-cloud-solutions/kubebolt/helm/kubebolt \
  --version 2.6.6 -n kubebolt --reset-then-reuse-values
```

Use the namespace you installed into: `helm list -A | grep kubebolt` shows it.
`--reset-then-reuse-values` needs Helm 3.14+, and passing your values file
(`-f`) works too. Do not use `--reuse-values`: it keeps the previous chart's
defaults, pinned image tags included, so the Azure MCP Server sidecar would
stay on 3.0. Step by step, what to expect, rollback, and what each version asks
of you when you skip some:
[Upgrade](https://github.com/clm-cloud-solutions/kubebolt/blob/main/deploy/helm/kubebolt/README.md#upgrade).

**If you pinned the Azure MCP Server sidecar image yourself** (in your values,
or by mirroring it into a private registry), move it to `4.0.0-beta.6`. The API
speaks to 4.0. With Docker Compose, the `azure` profile pulls the new image.

The agent stays on 1.4.9: there is no agent release with 2.6.6. On a cluster
with thousands of workloads, raise the memory limit on the agent's release
with `--set resources.limits.memory=512Mi`, or follow the command the
*OOMKilled* insight gives.
