# KubeBolt 2.5.2 — Kobi gets a face, and the YAML tab keeps what it hides

Drop-in over 2.5.1. No schema change and no migration. The agent moves to
**1.4.7**, a dependency update.

## Saving the YAML tab no longer overwrites the values it hides

The YAML tab hides every Secret value, the ConfigMap values that look like
credentials and the `kubectl.kubernetes.io/last-applied-configuration`
annotation. The editor sent that same text back as a full update, so a save
without any change:

- wrote `REDACTED` over every value of a Secret. `REDACTED` is valid base64,
  so the API server accepted it and stored six bytes of garbage;
- turned every hidden ConfigMap value into the text `REDACTED`;
- dropped `last-applied-configuration` from any resource.

The save now reads the object first and puts back what the viewer hid. A
`REDACTED` under a key the object does not have, and YAML that names another
object, are refused with a 400. While you edit a Secret or a ConfigMap with
hidden values, the tab says how to change one: for a Secret, keep `data` as it
is and add the new value in plain text under `stringData`.

**If you saved a Secret or a ConfigMap from the YAML tab before 2.5.2**, check
it. A damaged Secret value decodes to exactly `REDACTED`:

```bash
kubectl get secrets -A -o json | jq -r '.items[] | .metadata as $m
  | (.data // {}) | to_entries[] | select((.value | @base64d) == "REDACTED")
  | "\($m.namespace)/\($m.name): \(.key)"'
kubectl get configmaps -A -o json | jq -r '.items[] | .metadata as $m
  | (.data // {}) | to_entries[] | select(.value == "REDACTED")
  | "\($m.namespace)/\($m.name): \(.key)"'
```

Restore those values from their source. An object saved that way also lost its
`last-applied-configuration`: its next `kubectl apply` cannot tell which fields
you removed from the manifest, so it keeps them that one time and writes the
annotation again.

## New and edited Secrets refuse values that would be stored as garbage

Checking for the word `REDACTED` is not enough. Any plain text that uses only
the base64 alphabet and whose length is a multiple of four (`hola`,
`password`, `admin123`) is valid base64 too, and the API server stores it as a
few bytes of garbage, on create and on edit. **New resource** and the YAML tab
now check what you wrote the way the API server decodes it:

- `REDACTED` with no stored value behind it is refused: on create, under any
  key; on edit, under a key the object does not have.
- A value under a Secret's `data` or a ConfigMap's `binaryData` that is not
  base64 is refused with a 400 that points at `stringData` (or `data`). On
  create it used to be a 500.
- A value under a Secret's `data` that decodes to binary is refused, naming its
  keys. **Keep as binary** resends it as written, for a keystore or a key file
  written on purpose; the audit trail records the choice. Values already stored
  are never checked, so a binary Secret stays editable.

Every problem comes back in one message, one line each.

## Kobi has a face

Sentinel replaces the Sigil on Kobi's controls: a light shell, a dark visor,
two green eyes and the presence dot above.

- **The floating button is the head**, floating on its own shadow. A pill beside
  it says what Kobi is doing whenever it is not just watching
  (*Investigating · Logs · payments-api*). On hover or focus the head lifts and
  the dot appears with the live state.
- **The panel header** shows the live state, and says it in words on its second
  line.
- **The eyes say the state**: narrowed while it investigates, wide and round
  while it waits for your approval, a thin band that does not blink while it
  changes something, taking turns while it verifies. The dot's color and shape
  say it too, so the state reads without color and without motion.
- *Ask Kobi*, the message avatars, the Home panel and the AI administration
  carry the still face.
- **The sign-in panel** tells the site's story, and its console shows Kobi
  working an incident beat by beat, stopping for your approval.

## Every change says who made it

Every write KubeBolt made carried the field manager `kubebolt`, whether a person
or Kobi asked for it, and the audit trail took its source from a header the
client set. The actor now comes from who is signed in:

- **Kobi's writes carry the field manager `kubebolt-kobi`**, and only from a
  person's session, for a conversation that is theirs. Everything else
  KubeBolt writes stays `kubebolt`. `kubectl get <kind> <name> -o yaml
  --show-managed-fields` shows which.
- The audit trail records `ui` for a person in a session and `api` for an API
  key (keys used to be recorded as `ui`). A source the client claims but the
  server does not believe stays in the record as `claimedSource`.

## Smaller fixes

- **Turning Kobi's fallback off stays off** when the environment defines one
  (`KUBEBOLT_AI_FALLBACK_*`); before, the env fallback came back on the next
  read. A stored override also no longer rewrites the env fallback until a
  restart.
- **An address no route matches shows a 404 page** instead of a blank screen,
  and `/<unknown>/<namespace>/<name>` no longer reads "Access Restricted".
- **The logo inside the app is the Split Bolt**, as the favicon already was.
- **The cluster KubeBolt runs in stays monitored** while you look at another
  cluster. Fleet showed it as NO DATA about 45 minutes after a switch.
- **The web gets its own ServiceAccount** (`<release>-web`, bound to nothing,
  token not mounted). Cloud identities tied to the API's ServiceAccount (IRSA,
  EKS Pod Identity, Azure Workload Identity) no longer reach the web pod. New:
  `mcpConnectors.aws.webIdentity`, an AWS identity for the API outside EKS.
- The AWS connector's setup guide opens with what keeps the connection safe,
  as facts you can check in your own account.
- **Sign in** is no longer disabled over fields the browser filled in.

## Security

- `golang.org/x/net` 0.62.0 (CVE-2026-78661, CVE-2026-97045) and
  `golang.org/x/crypto` past GO-2026-5932, in the API and the agent.
- `react-router` 6.30.6 (CVE-2026-40181, CVE-2026-53668). The other two
  advisories against 6.x are fixed only in 7: CVE-2026-53666 is server
  rendering, which KubeBolt does not use, and for CVE-2026-53669 the sign-in
  redirect now refuses `/\host` and `/%5Chost`.

## Upgrading

```bash
helm upgrade kubebolt oci://ghcr.io/clm-cloud-solutions/kubebolt/helm/kubebolt --version 2.5.2
helm upgrade kubebolt-agent oci://ghcr.io/clm-cloud-solutions/kubebolt/helm/kubebolt-agent --version 1.4.7
```

2.5.2 also runs with agent 1.4.6; 1.4.7 only carries the dependency update.

- **OpenShift:** the web now runs under `<release>-web`. An SCC granted to the
  API's ServiceAccount no longer covers it, and it needs none
  (`restricted-v2`). See the OpenShift guide.
- Set `web.serviceAccount.create=false` to run the web under
  `web.serviceAccount.name`, or the namespace's default.

Do not use `--reuse-values` across chart versions; pass your values file
(`-f`) or `--reset-then-reuse-values`.
